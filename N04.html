ບົດທີ 4: ຕັ້ງຄ່າ nuxt.config.ts, Plugins ແລະ Assets

ຮຽນຮູ້ການປັບແຕ່ງລະບົບ Nuxt 4 ຜ່ານ nuxt.config.ts, ການຂະຫຍາຍຄວາມສາມາດດ້ວຍ Plugins ໃນ app/plugins/, ແລະ ການຈັດການຮູບພາບ & Stylesheets ຜ່ານ Assets.

1 ການຕັ້ງຄ່າໄຟລ໌ nuxt.config.ts

ໄຟລ໌ nuxt.config.ts ແມ່ນຫົວໃຈຫຼັກໃນການຕັ້ງຄ່າ Nuxt Application ໂດຍໃຊ້ຟັງຊັນ defineNuxtConfig():

📦 modules: [...]

ຕິດຕັ້ງສ່ວນເສີມ Official Modules ເຊັ່ນ: `@nuxtjs/tailwindcss`, `@pinia/nuxt`, `@vueuse/nuxt` ໂດຍ Nuxt ຈະ Configure ໃຫ້ອັດຕະໂນມັດ.

🔑 runtimeConfig

ຈັດການ Environment Variables ລະຫວ່າງ Private Keys (ເຊີບເວີເທົ່ານັ້ນ) ແລະ Public Keys ທີ່ໃຊ້ໃນ Browser ຜ່ານ useRuntimeConfig().

🏷️ app.head

ຕັ້ງຄ່າ Meta Tags, Title Template, Favicon, ແລະ Google Web Fonts ແບບ Global ໃຫ້ກັບທຸກໜ້າເວັບ.

🎨 css: [...]

ນຳເຂົ້າ Global Stylesheets ເຊັ່ນ: ~/assets/css/main.css ເພື່ອໃຫ້ໂຫຼດໃນທຸກ Component.

nuxt.config.ts 
// https://nuxt.com/docs/api/configuration/nuxt-config
export default defineNuxtConfig({
  // ເປີດໃຊ້ງານ Nuxt DevTools
  devtools: { enabled: true },

  // ເຊື່ອມໂຍງ Global CSS / Tailwind
  css: ['~/assets/css/main.css'],

  // Modules ສ່ວນເສີມ
  modules: [
    '@nuxtjs/tailwindcss'
  ],

  // ຕັ້ງຄ່າ Global HTML Head & SEO
  app: {
    head: {
      title: 'Nuxt 4 Course 2027',
      htmlAttrs: { lang: 'lo' },
      meta: [
        { charset: 'utf-8' },
        { name: 'viewport', content: 'width=device-width, initial-scale=1' },
        { name: 'description', content: 'ຮຽນຮູ້ Nuxt 4 ພາສາລາວ' }
      ],
      link: [
        { rel: 'icon', type: 'image/x-icon', href: '/favicon.ico' }
      ]
    }
  },

  // ຈັດການ Environment Variables
  runtimeConfig: {
    apiSecret: 'my-secret-token-123', // ເຂົ້າເຖິງໄດ້ສະເພາະ Server Side
    public: {
      apiBase: 'https://api.example.com' // ເຂົ້າເຖິງໄດ້ທັງ Client & Server
    }
  }
})

2 ການສ້າງ ແລະ ໃຊ້ງານ Plugins (app/plugins/)

Nuxt 4 ຈະອ່ານໄຟລ໌ທັງໝົດໃນໂຟລເດີ app/plugins/ ແລະ Register ໃຫ້ອັດຕະໂນມັດເມື່ອ Vue App ເລີ່ມຕົ້ນເຮັດວຽກ.

📌 ກົດລະບຽບການຕັ້ງຊື່ໄຟລ໌ Plugins:
  • myPlugin.ts — ເຮັດວຽກທັງຝັ່ງ Client ແລະ Server
  • myPlugin.client.ts — ເຮັດວຽກສະເພາະຝັ່ງ Browser/Client ເທົ່ານັ້ນ (ເຊັ່ນ Toast Notification, Chart.js)
  • myPlugin.server.ts — ເຮັດວຽກສະເພາະຝັ່ງ Node/Nitro Server ເທົ່ານັ້ນ
app/plugins/formatters.ts 
export default defineNuxtPlugin((nuxtApp) => {
  return {
    provide: {
      // ສ້າງ Helper Function `$formatDate` ໃຫ້ໃຊ້ໄດ້ທົ່ວທຸກ Component
      formatDate: (dateString: string) => {
        const date = new Date(dateString)
        return date.toLocaleDateString('lo-LA', {
          year: 'numeric',
          month: 'long',
          day: 'numeric'
        })
      },
      // ສ້າງ Helper `$currency` ສຳລັບຈັດຮູບແບບເງິນກີບ (LAK)
      currency: (amount: number) => {
        return new Intl.NumberFormat('lo-LA', { style: 'currency', currency: 'LAK' }).format(amount)
      }
    }
  }
})
ວິທີເອີ້ນໃຊ້ Plugin ໃນ Component: app/pages/index.vue 
<script setup lang="ts">
// ເອີ້ນໃຊ້ຜ່ານ useNuxtApp()
const { $formatDate, $currency } = useNuxtApp()
const today = $formatDate(new Date().toISOString())
const price = $currency(150000)
</script>

<template>
  <div>
    <p>ວັນທີ: {{ today }}</p>
    <p>ລາຄາ: {{ price }}</p>
    <!-- ຫຼື ເອີ້ນໃຊ້ໃນ Template ໂດຍກົງ -->
    <p>{{ $currency(50000) }}</p>
  </div>
</template>

3 ການຈັດການ Assets: ຄວາມແຕກຕ່າງລະຫວ່າງ assets/ vs. public/

Nuxt 4 ມີ 2 ວິທີຫຼັກໃນການຈັດເກັບໄຟລ໌ຮູບພາບ, Stylesheets, Fonts ແລະ ໄຟລ໌ຄົງທີ່:

ລັກສະນະການໃຊ້ງານ ໂຟລເດີ assets/ (Processed Assets) ໂຟລເດີ public/ (Static Assets)
ການປະມວນຜົນ (Build Step) ຜ່ານ Vite, PostCSS, Sass, Minification & Hash ໄຟລ໌ ບໍ່ມີການປະມວນຜົນ, ຖືກສົ່ງໄປທີ່ Root URL ໂດຍກົງ
ປະເພດໄຟລ໌ທີ່ເໝາະສົມ Custom CSS, SCSS, SVG Icons ທີ່ຕ້ອງການ Optimize, Fonts ພາຍໃນ `favicon.ico`, `robots.txt`, `sitemap.xml`, ຮູບພາບຂະໜາດໃຫຍ່, PDF ດາວໂຫຼດ
ວິທີອ້າງອີງ Path ໃນ Code ~/assets/img/logo.png /favicon.ico ຫຼື /banner.png
// ຕົວຢ່າງການໃຊ້ງານຮູບພາບໃນ Template:
<!-- 1. ຮູບພາບຈາກ public/ (ອ້າງອີງຈາກ Root / ໄດ້ທັນທີ) -->
<img src="/banner.png" alt="Public Banner" />
<!-- 2. ຮູບພາບຈາກ assets/ (Import ຜ່ານ Vite Build Pipeline) -->
<img src="~/assets/images/logo.svg" alt="Asset Logo" />

4 ສະຫຼຸບ ແລະ ຂໍ້ແນະນຳໃນການພັດທະນາ (Best Practices)

🛡️

ຄວາມປອດໄພຂອງ Secret Keys

ຢ່າວາງ API Secret Keys ໄວ້ໃນ runtimeConfig.public ເພາະຜູ້ໃຊ້ທຸກຄົນຈະສາມາດເຫັນໄດ້ເທິງ Browser.

🚀

ໃຊ້ Client-Only Plugin ເທົ່າທີ່ຈຳເປັນ

ຫາກ Plugin ໃດທີ່ເຂົ້າເຖິງ window ຫຼື document ໃຫ້ໃສ່ນາມສະກຸນ .client.ts ສະເໝີ.

⚡

Assets Optimization

ໃຊ້ໂຟລເດີ assets/ ສຳລັບຮູບພາບ UI Icons ທີ່ຕ້ອງການໃຫ້ Vite ຊ່ວຍ Optimize ແລະ Cash-Busting.
