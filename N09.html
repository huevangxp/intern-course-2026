ບົດທີ 9: Route Middleware & Authentication Guards

ຮຽນຮູ້ວິທີປົກປ້ອງໜ້າເວັບ (Protected Routes), ການສ້າງລະບົບ Auth Guard, ການກວດສອບ Login Token ຜ່ານ Cookie, ການ Redirect ໄປໜ້າ Login ດ້ວຍ navigateTo(), ແລະ ການແບ່ງສິດຜູ້ໃຊ້ Role-Based Access Control (RBAC).

1 Route Middleware ແມ່ນຫຍັງ? ແລະ 3 ປະເພດໃນ Nuxt 4

Route Middleware ແມ່ນ Function ທີ່ຈະຖືກເອີ້ນເຮັດວຽກ "ກ່ອນ" ທີ່ຜູ້ໃຊ້ຈະເຂົ້າເຖິງໜ້າເວັບໃດໜຶ່ງ (Before Navigation). ມັນເຮັດໜ້າທີ່ຄືກັບ "ຕຳຫຼວດກວດຄົນເຂົ້າເມືອງ" ເພື່ອກວດສອບວ່າ ຜູ້ໃຊ້ Login ແລ້ວບໍ? ມີສິດເຂົ້າເຖິງໜ້ານີ້ຫຼືບໍ່? ຫາກບໍ່ມີສິດ ລະບົບຈະ Reject ຫຼື Redirect ອອກໄປທັນທີ.

🏷️

1. Named Middleware

ສ້າງໄວ້ທີ່ app/middleware/auth.ts ແລະ ເລືອກເອີ້ນໃຊ້ສະເພາະບາງໜ້າຜ່ານ definePageMeta.

🌐

2. Global Middleware

ໃສ່ນາມສະກຸນ .global.ts (ເຊັ່ນ app/middleware/log.global.ts) ເພື່ອໃຫ້ເຮັດວຽກ ທຸກໆໜ້າ ອັດຕະໂນມັດ.

📄

3. Inline / Anonymous

ຂຽນ Function Middleware ໂດຍກົງພາຍໃນໄຟລ໌ໜ້າເວັບ Page Component ນັ້ນໆ ໂດຍບໍ່ຕ້ອງສ້າງໄຟລ໌ແຍກ.

2 ສ້າງ Named Auth Guard (app/middleware/auth.ts)

ໃນ Nuxt 4, ພວກເຮົາໃຊ້ Helper defineNuxtRouteMiddleware((to, from) => { ... }). ຫາກກວດພົບວ່າບໍ່ມີ Auth Token ຈະໃຊ້ navigateTo() ເພື່ອສົ່ງຜູ້ໃຊ້ໄປໜ້າ Login:

app/middleware/auth.ts 
export default defineNuxtRouteMiddleware((to, from) => {
  // 1. ດຶງ Token ຈາກ Cookie (ໃຊ້ໄດ້ທັງຝັ່ງ Server SSR ແລະ Client)
  const token = useCookie('auth_token').value

  // 2. ຖ້າບໍ່ມີ Token (ຍັງບໍ່ທັນ Login)
  if (!token) {
    // ແຈ້ງເຕືອນ log ຫຼື redirect ໄປໜ້າ Login ພ້ອມແນບ redirect query param
    return navigateTo({
      path: '/login',
      query: { redirect: to.fullPath }
    })
  }

  // 3. ຖ້າມີ Token ອະນຸຍາດໃຫ້ຜ່ານໄປໜ້າປາຍທາງໄດ້
})

3 Global Middleware & ການຈັດລຳດັບການເຮັດວຽກ

Global Middleware ຈະເຮັດວຽກໃນທຸກໆການປ່ຽນ Route. ພວກເຮົາສາມາດກຳນົດລຳດັບ (Execution Order) ໄດ້ໂດຍການໃສ່ຕົວເລກນຳໜ້າຊື່ໄຟລ໌:

app/middleware/01.analytics.global.ts 
export default defineNuxtRouteMiddleware((to, from) => {
  // ເຮັດວຽກເປັນອັນດັບ 1 ທຸກໆຄັ້ງທີ່ມີການກົດປ່ຽນໜ້າ
  if (import.meta.client) {
    console.log(`[Navigation] ຜູ້ໃຊ້ກຳລັງຍ້າຍຈາກ: ${from.path} ໄປຫາ: ${to.path}`)
  }
})

4 Role-Based Access Control (RBAC: Admin vs Teacher vs Student)

ບາງໜ້າເວັບ (ເຊັ່ນ: ການຈັດການເງິນເດືອນ, ການລຶບຂໍ້ມູນອາຈານ) ຕ້ອງການສິດສະເພາະ Admin ເທົ່ານັ້ນ. ພວກເຮົາສາມາດສ້າງ app/middleware/admin-only.ts:

app/middleware/admin-only.ts 
export default defineNuxtRouteMiddleware((to, from) => {
  const userRole = useCookie('user_role').value // 'admin' | 'teacher' | 'student'

  if (userRole !== 'admin') {
    // ຖ້າບໍ່ແມ່ນ Admin ໃຫ້ສົ່ງ Error 403 Forbidden ຫຼື Redirect ໄປໜ້າ Home
    throw createError({
      statusCode: 403,
      statusMessage: 'ທ່ານບໍ່ມີສິດເຂົ້າເຖິງໜ້ານີ້ (Forbidden: Admin Only)'
    })
  }
})

5 ວິທີນຳໃຊ້ Middleware ໃນ Page Component

ໃນໄຟລ໌ໜ້າເວັບ (app/pages/teachers/index.vue), ພວກເຮົາຈະໃຊ້ Compiler Macro definePageMeta():

app/pages/teachers/manage.vue 
<script setup lang="ts">
// ປະກາດ Middleware ທີ່ຕ້ອງການໃຫ້ເຮັດວຽກ (ສາມາດໃສ່ຫຼາຍຕົວຕາມລຳດັບ Array)
definePageMeta({
  middleware: ['auth', 'admin-only']
})
</script>

<template>
  <div class="p-6">
    <h1>ໜ້າຈັດການຄູ-ອາຈານ (ສຳລັບ Admin ທີ່ Login ແລ້ວເທົ່ານັ້ນ)</h1>
  </div>
</template>

Live Nuxt Guard Simulation

7 ໂຄດຕົວຢ່າງສົມບູນ: ໜ້າ Admin Dashboard ພ້ອມ Auth Guard

ຕົວຢ່າງການຂຽນໄຟລ໌ app/pages/admin/dashboard.vue ທີ່ປົກປ້ອງດ້ວຍ Middleware ແລະ ສະແດງປຸ່ມ Logout:

app/pages/admin/dashboard.vue 
<script setup lang="ts">
// 1. ປ້ອງກັນໜ້ານີ້ດ້ວຍ auth ແລະ admin-only middleware
definePageMeta({
  middleware: ['auth', 'admin-only']
})

// 2. ດຶງຂໍ້ມູນ User Profile
const user = useCookie('auth_user')

// 3. ຟັງຊັນອອກຈາກລະບົບ (Logout)
const handleLogout = () => {
  useCookie('auth_token').value = null
  useCookie('user_role').value = null
  useCookie('auth_user').value = null
  
  // ສົ່ງກັບໄປໜ້າ Login
  navigateTo('/login')
}
</script>

<template>
  <v-container class="py-8">
    <v-card elevation="2" class="p-6 rounded-2xl bg-surface">
      <div class="d-flex justify-space-between align-center mb-4">
        <h1 class="text-h5 font-weight-bold">Admin Dashboard</h1>
        <v-btn color="error" variant="tonal" prepend-icon="mdi-logout" @click="handleLogout">
          ອອກຈາກລະບົບ
        </v-btn>
      </div>
      <p>ຍິນດີຕ້ອນຮັບ, ທ່ານເຂົ້າສູ່ລະບົບໃນຖານະ: <strong class="text-teal">Admin</strong></p>
    </v-card>
  </v-container>
</template>

8 ຂໍ້ຄວນລະວັງ & Best Practices ກ່ຽວກັບ Route Middleware

⚠️ ລະວັງບັນຫາ Infinite Redirect Loop!

ຖ້າ Middleware ກວດສອບວ່າບໍ່ມີ Token ແລ້ວສັ່ງ navigateTo('/login') ໂດຍບໍ່ກວດສອບກ່ອນວ່າໜ້າປັດຈຸບັນແມ່ນ /login ແລ້ວຫຼືບໍ່, ລະບົບຈະ redirect ວົນຊ້ຳບໍ່ສິ້ນສຸດ. ໃຫ້ໃສ່ເງື່ອນໄຂ if (!token && to.path !== '/login') ສະເໝີ!

💡 ໃຊ້ useCookie() ແທນ localStorage

ເພາະ Nuxt 4 ເຮັດວຽກແບບ Server-Side Rendering (SSR). ໃນຕອນ Render ຢູ່ Server ຈະບໍ່ມີ window ຫຼື localStorage. ການໃຊ້ useCookie() ຈະເຮັດໃຫ້ Middleware ອ່ານ Token ໄດ້ຢ່າງຖືກຕ້ອງທັງຝັ່ງ Server ແລະ Client.

⚡ ກວດສອບ Token Expiration (ວັນໝົດອາຍຸ)

ຢ່າກວດພຽງແຕ່ມີ Token ຫຼື ບໍ່, ຄວນກວດສອບວ່າ Token ໝົດອາຍຸຫຼືຍັງ ຫາກໝົດອາຍຸໃຫ້ Redirect ໄປ Login ພ້ອມລຶບ Cookie ເກົ່າຖິ້ມ.
